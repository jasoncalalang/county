# County backend implementation plan

> **For agentic workers:** Use executing-plans to implement task-by-task.

**Goal:** Build the v1 ordering backend, without web or deployment.
**Architecture:** Quarkus REST with authenticated identity-derived tenancy, PostgreSQL/Flyway and plain Java domain rules. Read architecture commit 2d00e763 as canonical working baseline.
**Tech Stack:** Java 21, Gradle, Quarkus, PostgreSQL, JUnit, REST-assured.
**Spec:** county-architecture/design/2026-10-31-v1-functional-spec.md, with approved 2026-10-16 design.

## Global constraints
- No Docker required; integration tests use COUNTY_TEST_JDBC_URL.
- No request supplies tenant_id. Foreign resources return 404.
- Server computes prices, totals, dates and status; orders are immutable.
- No production credentials, deployment or frontend changes.

## Review focus
- Cross-tenant and cross-reseller guessed IDs must not leak data.
- Duplicate concurrent submissions must not allocate duplicate orders or numbers.
- A replay with changed payload must not mutate the original order.
- Cutoff boundaries and non-delivery days must use Asia/Manila.
- Malformed money, quantity, mobile and identity inputs must not become 500s.

## Tasks
- [x] Foundation: generated Gradle/Quarkus skeleton, explicit DB profiles, RFC9457 errors and migration. Integration test initially asserts missing API routes then passes once implemented.
- [x] Pure domain: failing JUnit tests for calendar/transition/money/mobile rules, minimal implementation, green unit suite.
- [x] Owner API: REST-assured tests for onboarding/settings/products/resellers and tenant isolation, then implement identity resolver and resource-scoped queries.
- [x] Ordering API: REST-assured tests for token catalog, placement/replay, confirmation/cancellation/delivery/paid and production totals, then transactional service implementation. Scope idempotency by tenant and verify reseller ownership.
- [x] Verify: full integration suite on disposable real Postgres; package build; independent review; fix findings, commit and draft PR. Document remaining gaps honestly.

## File structure
- api/src/main/java/ph/com/ridgewell/county/domain: framework-independent rules.
- api/src/main/java/ph/com/ridgewell/county/api: DTOs, REST resources, identity and exception mapping.
- api/src/main/java/ph/com/ridgewell/county/persistence: tenant-scoped SQL repository/service.
- api/src/main/resources/db/migration: versioned schema.
- api/src/test/java: domain and HTTP integration tests, test-only OIDC identity setup.

## Execution results

Domain tests observed red before implementation. HTTP acceptance and isolation tests
observed red before resources were implemented. Independent review regression tests
reproduced product-rename aggregation, link retrieval and filter issues; fixes verified.
Local signed-JWT tests exercise real OIDC verification. The follow-up closes the
provider/user identity and typed response contract gaps described below.

Final local verification: Java 21 + Gradle 9.7.0, PostgreSQL 17.6, `clean build`
and follow-up `build`: 32 tests, zero failures/errors/skips. No Docker, real Google
credentials, frontend or deployment involved. Remote CI is reported separately.
